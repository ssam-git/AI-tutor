API Learning Sandbox

Pick a scenario and press Run. Watch one API call travel through client code → the wire → server code → the wire → client code, one step at a time, with the executing line highlighted in both panes and a timestamped request/response trace underneath.

  • 4 API types, same scenario: REST, GraphQL, gRPC, WebSocket
  • 4 languages on each side: Python, JavaScript, Java, C#
  • 6 scenarios: package search, token exchange, weather + cache, image bytes, 3 MB chunked video, live server push
  • Real detail: headers, status codes, Content-Length, TLS/keep-alive, TCP frames, sendfile(2), bcrypt cost, cache hits
  • Step forward/back, slow-mo or instant, explanations on/off; swipe between panels on a phone
  • Drag the grips between panels to resize them, and the page remembers

MCP Learning Sandbox

Same console, new protocol. Watch one tool call travel through the model → the MCP client → JSON-RPC 2.0 on a transport → the MCP server → back, and switch the protocol revision to watch the start of the conversation change shape.

  • 3 protocol revisions side by side: 2025-03-26, 2025-11-25 and the current 2026-07-28 — the initialize handshake, the session id and server-initiated elicitations all appear and disappear
  • 2 transports: stdio (child process, one JSON line per message) vs Streamable HTTP (Mcp-Method headers, no session id)
  • 4 scenarios: cold start (server/discover + tools/list), a tool call, tool failure vs protocol failure, and a server that has to ask a human before it acts
  • Real message shapes: isError vs a JSON-RPC error, structuredContent, and input_required retried with requestState + inputResponses
  • Server in Python (FastMCP) or the TypeScript SDK; the client in TypeScript or Python — and the Python client is where you see mode="legacy" appear for the old revisions that could send requests back
  • Drag the grips between panels to resize them, and the page remembers

How these are built

Every tutorial is one self-contained HTML file — plain HTML, CSS and JavaScript, no build step, no dependencies, no analytics, no network requests. They are written with an AI assistant and then reviewed and fixed by hand, which is why each one fits in a single file you can read top to bottom and save to your desktop. Serving them is just static files: push to main and GitHub Pages republishes. The two sandboxes share one step engine: the block is copied into each file, and dev/check-shared.js fails if the two copies drift apart.
